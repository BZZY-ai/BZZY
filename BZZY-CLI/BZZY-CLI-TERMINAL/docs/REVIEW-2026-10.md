# Assessment of the external code review

Historical assessment of the earlier build. The current CLI has since gained a
verified macOS sandbox adapter, and the Telegram integration has been removed.
See README.md and INTEGRATION.md for current platform and integration behavior.

Reviewed against `cca1571`. The supplied `bzzy_improvements.txt` is input to this assessment; its severity ratings and proposed fixes are not adopted automatically. This change addresses reproducible defects and bounded improvements without silently changing permission or persistence guarantees.

| Finding | Assessment and action |
| --- | --- |
| S1: multi-agent modes unavailable on macOS | Correct. Coordinators and delegate goals now reject unsupported isolation before starting model work. A private directory and an approval callback do not enforce a filesystem boundary. A native macOS worker sandbox remains separate work; this patch does **not** claim macOS multi-agent parity. Explicit read-only/contracts remain fail-closed. |
| S2: full-table polling | Correct. Added indexes and query filters for state, session, parent session and working directory. Runtime scheduling, snapshots, controls, execution reservation and Telegram queues use filtered queries. Snapshot reads fetch only the latest execution. SSE adoption, event coalescing, retention and less frequent idle polling remain future improvements. |
| S3: repeated copies and disk growth | Correct. Snapshots and worker copies request filesystem copy-on-write, with normal-copy fallback. No automatic history or evidence deletion: export, recovery, reviewed patches and skill generation still reference those files. Reachability-aware garbage collection remains future work; reflinks reduce copy cost but do not impose a retention limit. |
| S4: unguarded timers | Correct for the cited heartbeat, controller, coordinator, scheduler and SSE callbacks. Added non-overlapping guarded intervals with rate-limited, redacted diagnostics. Repeated runner/coordinator persistence failures request a stop. Spawn callbacks contain persistence exceptions. Cleanup closes independent resources even if one close fails, and releases the session lock even when final persistence fails. This is not a promise that execution can continue on a full or corrupt disk. |
| S5: unanswered approvals | Correct. Questions expire after ten minutes by default; an expired approval is denied. `inputTimeoutSeconds` configures the timeout. Waiting state survives a stale engine save, and the session browser prioritizes it. Goal input notifications use the existing configured notification transport and include an attach command. No new unattended permission grant is introduced. |
| S6: snapshot bounds | Correct that the defaults exclude large workspaces. Limits are now configurable; manifests hash incrementally and avoid quadratic file counting. Existing limits remain the defaults. Silently skipping files is rejected: an incomplete baseline can mistake a missing original file for a new file during review/apply. Snapshot records retain their limits for later comparisons. Evidence artifacts keep their independent 20 MiB limit. |
| S7: private peer changes reported complete | Correct for free-text goals: model judgment alone could pass with unapplied edits. Group acceptance now compares peer changes with the actual project, refuses completion while integration is pending, and records paths/change lists. The summary shows the private workspaces. A selection UI and conflict-aware group integration remain future work; changes are not applied automatically. |
| S8: oversized provider handoff | Correct. Handoffs read recent events backwards and bound history to 30 messages / 96 KiB of event data, including the single-giant-message case. Historical events stay saved. This bounds handoff growth; model-specific context error recovery remains future work. |
| S9: PID-only locks | Correct for new locks. Locks now store process birth identity and publish complete contents atomically. Reused PID identities and old incomplete files are recoverable; active locks remain protected. Legacy PID-only locks are accepted conservatively until their owner exits. EPERM does not prove a process is dead and is **not** authority to remove its lock. |
| S10: runtime environment restart loop | Correct. Caller environments are supplied per execution in private 0600 runtime files, inherited by mode children and removed at terminal execution states. API keys are not stored in execution records or event exports. PATH/key differences no longer restart the singleton. The build digest covers all source, assets and launcher files. Safe/idempotent HTTP calls retry transient transport failures. |
| S11: nested goal resume | Correct. An in-chat resume returns to the existing chat loop rather than opening another one. |
| S12: unbounded goal/besties work | Goal budgets are intentionally opt-in; silently adding universal goal ceilings changes the product's persistent-goal semantics. Existing runtime/token/turn controls remain. Besties feedback restarts now have a configurable six-exchange cap per peer; explicit resume opens another bounded exchange while retaining the discussion. Repetition-based stopping remains future work. |
| S13: RPC error handling | Partly accepted. Stray non-JSON stdout lines are ignored with a diagnostic. Handler failures are reported separately from JSON failures. Ignoring a failed state handler is rejected: losing a completed-turn notification or a persistence error can itself cause a hang or incorrect completion. |
| S14: UTF-8 chunk corruption | Correct. Tool sockets and verification streams use incremental UTF-8 decoding; HTTP bodies collect bytes before decoding. Request/response limits count bytes. Regression checks split accented characters and emoji between writes. |
| S15: export transaction and contents | Export/skill context reads now use a deferred WAL transaction and select events by the included sessions, so they do not reserve the writer lock or load every project's events. Record relationship discovery still examines the record graph. Full-workspace export is an existing, tested round-trip contract, including .env and dependencies. Default exclusions would change that behavior; an explicit filtered-export option remains future work. Global bzzy credentials and transient execution environment files remain outside the bundle. |
| S16: project pollution | Generated `.bzzy/.gitignore` now ignores all generated content; the old generated rules migrate, custom rules stay intact. Routine agent-output/HTTP artifacts stay in private storage instead of being duplicated into the project; explicitly captured evidence still mirrors there. A consistent private project-storage fallback for unwritable directories and home-directory workspaces remains future work. |
| S17: security posture | Mixed scope. The enforcement profile controls writes/network, not complete confidentiality of the host filesystem. Masking only a few secrets would not establish that guarantee, and backends still need their native auth stores. Stronger read isolation, config-store isolation and explicit trust for repository constraints need a separate permission design and tests. Telegram approval is an intentional feature of the explicitly paired account; optional approval restrictions remain future work. |
| S18: backend protocol drift | A real compatibility risk, but removing native auth checks or caching an invalid login without invalidation would worsen diagnosis. Existing version checks, native model discovery and smoke checks remain. Capability negotiation and a backend compatibility CI matrix remain future work. |

Additional fixes: `/providers` changes only the current conversation; `/default` saves the global selection. Automatic Telegram attachment keeps an existing conversation instead of moving it to the most recent terminal. Idle goal cancellation reports “cancelled,” cancellation errors retain cancelled execution state, recurring blockers keep their reason, missing/invalid cwd and missing memory input have useful errors, memory files resolve relative to `--cwd`, legacy sessions without `updatedAt` remain sortable, and older Node versions receive a clear requirement message before importing `node:sqlite`. The goal prompt now agrees with its actual report-tool schema.

The review's mascot statement needs qualification: full mascot frames advance at 10 Hz; the eye animation has a separate 60 Hz timer. No animation changes were necessary for these correctness fixes. Intentional repository artwork and user-created goal artifacts are not removed as unsolicited cleanup.

The more ambitious mode suggestions—independent adjudication, race mode, broadcast/quorum changes, automatic role assignment, Git worktrees and group apply—are product changes, not mechanical fixes. They are deferred rather than silently changing how the requested modes operate. Delegate mode continues to require attempted/reviewed worker work because that is its documented purpose.

The updated workflow remains a template in `docs/ci-platforms.yml`; it is not an active CI run. Native macOS execution has not been tested from this Linux workspace.

Continuation review also fixes incomplete snapshot-directory cleanup, validates input timeout settings before publishing questions, honors raised snapshot limits when checking peer integration, follows replacement runtime addresses during safe retries, and releases coordinator locks after initialization or result-write failures. Runner-death supervision briefly waits for the child exit callback so that startup failures retain their actual exit code. The restart regression now holds a runner on explicit input rather than assuming a short timed response is still running on a busy host.

Validation on Linux with the bundled Node 24.22.0: all 328 tests passed. An overlapping test run exceeded one terminal test's 30-second deadline; the fresh full run and independent goal/chat regressions passed. Tests cover indexed lookups, lock recovery, bounded handoffs, timer failures, approval expiry, UTF-8 chunk boundaries, exports with concurrent writers, private peer changes, snapshot limits, runtime reconnect capabilities, coordinator cleanup and besties exchange limits. Real Codex protocol/inference smoke checks used a loopback mock, and real Claude streaming/control initialization passed without inference. No paid model request or native macOS execution was exercised.

A scratch SQLite benchmark with 11,001 synthetic execution records and 100 repetitions measured average lookup times of 117.289 ms for the old full-scan/filter pattern, 0.163 ms for an indexed session lookup and 0.145 ms for the indexed active-state query. This measures those queries on this host under concurrent test load, not overall application throughput or macOS performance. The scratch database was removed afterward.
